D6 DICE HANDSPECIFICATION ← ゲームに戻る

ターン制カードバトル「DICE HAND」戦闘デモの全仕様。 定数・カード・役の各表は実装（src/data/）から実行時に生成しているため、 コードを変更すればこのページも自動的に追従する。

1. 概要

プレイヤーが複数の敵（CPU）と戦うターン制カードバトル。プレイヤーはデッキからカードを引き、ポイントを消費してカードを使用し、すべての敵のHPを0にすれば勝利する。

本デモは戦闘のコアルールが成立するかを確認することを目的とし、以下2つの画面で構成される。

  • DECK CONSTRUCTION — カード一覧から初期デッキ（6〜20枚）を構築する
  • BATTLE — 構築したデッキでCPUと戦う

戦闘は必ずデッキ構築から始まる。戦闘中はいつでも構築画面に戻れる（デッキ内容は保持される）。

本デモに含まれないもの

オンライン対戦、セーブ、アカウント、カード収集、ショップ、ストーリー、CPU側のカードシステム、高度なCPU思考、BGM・設定画面。

2. ゲーム定数

すべて src/data/constants.js の GAME_CONFIG で管理し、後から変更できる。

CPU HP・CPU攻撃力・プレイヤーHPは、貪欲AIによる400回の戦闘シミュレーション（平均43.4ダメージ/ターン）に基づき、勝率76%・平均8.5ターンになるよう設定している。

3. デッキ構築

カード一覧から + / − で枚数を増減し、6〜20枚にすると BATTLE START が有効になる。最小6枚は「5枚の手札 + 1枚のドロー」を引ける枚数。これらの制約は構築画面だけに掛かり、戦闘後のカード入手・削除には掛からない。

3.1 構築ルール

3.2 目の上限が持つ意味

「同じ目は最大4枚」は単一の目に寄せたデッキを防ぐための制約である。これがないと、同じ目だけを積んで SAME NUMBER ×2.5 を毎ターン成立させる構築が自明の最適解になってしまう。

デッキ枚数がちょうど20枚だった頃は、この制約により5種類以上の目が混ざることが保証されていた。枚数を自由にした現在は、その保証はない。

3.3 検証

デッキが不正な場合は理由を画面に表示し、BATTLE START を無効化する。検証内容は次のとおり。

  • 合計が6枚以上20枚以下であること
  • 攻撃カードが1枚以上あること
  • 各目の枚数が上限以下であること
  • 同名カードの枚数が上限以下であること

3.4 初期デッキ（初期構成・最小限）

目1〜6の攻撃カードを1枚ずつと、防御カード2枚の8枚。戦術カードや能力持ちのカードは、戦闘後の入手で増やしていく前提。

4. カード

4.1 データ構造

type Card = {
  id: string;              // 実体ごとの一意なID
  key: string;             // カタログ上の種別キー
  name: string;

  cost: number;            // 使用に必要なポイント
  attack: number;          // 基本攻撃力（戦術カードは 0）

  dieValue: 1|2|3|4|5|6;   // 現在の目（Tune Up / Tune Down で変化する）
  baseDieValue: 1|2|3|4|5|6; // 初期の目（変化の表示に使う）

  onUseAbility: Ability | null;      // 攻撃時に発動
  passiveAbility: Ability | null;    // 手札にある間つねに有効
  tacticalAbility: Ability | null;   // 攻撃せず手札を操作する
};

役はカード固有ではなく手札全体から判定するため、カード側に役データは持たせない。能力はすべてデータとして定義し、カード名ごとの分岐は書かない。

5. 戦闘フロー

5.1 戦闘開始

  1. プレイヤーHP・敵のHPを最大値にする（連戦ではプレイヤーHPは引き継ぐ）
  2. ポイントを初期値にする
  3. 構築したデッキを生成しシャッフルする
  4. デッキから5枚引く（ポイントを消費しない）
  5. ターン1を開始する

5.2 1ターンの進行

1. ドロー選択      DRAW（1ポイント）または SKIP
2. カード使用      攻撃・防御・戦術カードを、ポイントが続く限り何枚でも使う
                   （どのカードもターンを終了しない。1枚使うごとに残りの手札で役を判定し直す）
3. END TURN        プレイヤーが自分でターンを終了する（いつでも押せる）
4. 敵の行動        生き残っている敵が先頭から順に行動。シールドは順に削られる
5. ポイント回復
6. シールドをリセット
7. 手札を全て捨て、5枚引き直す
8. 次のターンへ

どちらかのHPが0以下になった時点で戦闘を終了する。

5.3 フェーズ

6. リソース

6.1 ポイント

カードの使用とドローに必要。ターン終了時に回復し、最大値を超えない。0未満にもならない。

point = fullRefill
  ? maxPoint                                  // 毎ターン上限まで全回復（貯められない）
  : Math.min(maxPoint, point + recovery)

開始値・上限・回復量・全回復の有無はデッキ構築画面の POINT RULES で変更できる（1〜20の整数。開始値は上限を超えない）。既定値は2章の定数（開始10・上限10・+5）。比較用に次のプリセットがある。設定は連戦中も引き継ぎ、戦闘画面のポイント欄にも表示する。

  • 標準：開始10 / 上限10 / +5
  • A：開始10 / 上限10 / +3
  • B：開始6 / 上限6 / +5
  • C：開始5 / 上限5 / 毎ターン5まで全回復

カードは種類を問わずポイントが続く限り何枚でも使えるため、ポイントが1ターンに使えるカード枚数の上限になる。

6.2 ドロー

ターン開始時に DRAW / SKIP を選ぶ。DRAW は1ポイントを消費して手札を1枚増やす。以下の場合は DRAW できない。

  • ポイントが不足している
  • 山札と捨て札の両方が空である

6.3 山札・捨て札・再構築

カードは常に「山札・手札・捨て札」のいずれかにあり、3つの合計は常にその戦闘のデッキ枚数に等しい。

deck.length + hand.length + discardPile.length === デッキ枚数

山札が尽きた状態でカードを引く必要が生じた場合、捨て札をシャッフルして山札を再構築し、続きを引く。山札・捨て札の両方が空になった時点で打ち切る。

6.4 シールド

ターンをまたがない。ターン終了時に0へ戻す。

シールドは防御カード（Brace 1・Parry 2：コスト1でシールド+10）と戦術カード Guard（コスト2でシールド+14）で得る。

防御カードは攻撃カードと同じく、カード選択 → EXECUTE（DEFEND）で使用する。攻撃と同じくターンは終了しない。防御値に役の倍率は掛からない。

シールドはCPUの攻撃を先に吸収し、残った分だけHPが減る。CPUの次の行動は常に予告されるので、必要なシールド量は常に計算できる。

incoming = intent.value + cpu.charge   // ATTACK のとき
absorbed = Math.min(shield, incoming)
taken    = incoming - absorbed
hp      -= taken

1ターンに複数枚使う場合、2枚目以降は1枚減った手札で役を判定し直すため、使うほど役が崩れる可能性がある。すべての敵のHPが0になった時点で、ターンの途中でも即座に勝利となる。

6.5 手札の総入れ替え

ターン終了時に手札をすべて捨て札へ送り、あらためて5枚引き直す。引き直しはポイントを消費しない。

これは「手札を1枚まで減らして SAME NUMBER を常に成立させる」退化戦術を防ぐための仕様である。毎ターン5〜6枚を消費するため、山札はおよそ4ターンで一巡する。

7. 役システム

カードを使用する直前の手札全体の目を見て役を判定し、攻撃力に倍率を掛ける。使用するカード自身も判定に含める（手札から取り除く前に判定する）。

7.1 役一覧

単独成立率は、目の上限4枚を満たす代表的な20枚デッキから5枚を引いた場合の実測値（20万回試行、重複適用を入れる前の計測）。重複適用後の期待倍率は1.66。もっとも多い組み合わせは PAIR 単独（21.9%）、TWO PAIR 単独（13.5%）、PAIR × THREE STRAIGHT（13.0%）。

7.2 系統と重複適用

役は系統（family）に属する。成立した役は系統をまたいで掛け合わせる。

同じ系統の役は互いに入れ子になっているため（PAIR ⊂ TWO PAIR ⊂ FULL HOUSE、THREE STRAIGHT ⊂ FOUR STRAIGHT）、まとめて掛けると同じ手札を多重に数えてしまう。そこで系統ごとに最も倍率の高い役をひとつだけ採用する。

3, 3, 3, 1, 1
  同じ目 : FULL HOUSE ×1.9   （THREE OF A KIND / TWO PAIR / PAIR は採らない）
  偶奇   : ODD        ×1.3
  →  ×1.9 × 1.3 = ×2.47

6, 6, 6, 6, 2
  同じ目 : FOUR OF A KIND ×2.25
  偶奇   : EVEN           ×1.3
  →  ×2.925

2, 3, 4, 4, 5
  同じ目 : PAIR          ×1.1
  連番   : FOUR STRAIGHT ×1.35
  →  ×1.485

ボーナス役の倍率は、旧値のボーナス部分（1を超える分）を半分にしたもの（例：×2.8 → ×1.9）。減算役 ×0.5 はそのまま。

EVEN / ODD はさらに ×1.3 に下げている。デッキを偶奇に寄せるだけで成立率を100%にでき、同じ寄せ方で同じ目の系統も成立しやすくなって掛け合わさるため、偶数のみのデッキが突出していた。12枚・各目4枚以下のデッキで手札5枚の期待倍率を全構成について計算すると、偶数のみは ×2.77 → ×1.90、均等（各目2枚）は ×1.23 → ×1.21 になる。

倍率が同じ役が並んだ場合は priority の高い方を採用する。いずれの系統も成立しなければ倍率 ×1 とする。

系統をまたぐ含意の除外

SAME NUMBER は「すべて同じ目」なので、偶奇も必ず揃う。これを EVEN / ODD と掛けると同じ事実を二重に数えることになるため、excludes: ["parity"] として偶奇系統を打ち消す。

2, 2, 2  →  SAME NUMBER ×2.5 のみ（EVEN とは重複させない）

7.3 減算役 1-2-3 と、その脱出

1・2・3 が揃うと ×0.5 が掛かる。減算も他の役と同様に掛け合わされる。

手札に4があれば 1-2-3 は成立しない。 1・2・3 は3連番そのものであり、この例外がないと減算役が STRAIGHT に埋もれて意味を持たなくなるためである。

1, 2, 3, 5, 6  →  THREE STRAIGHT ×1.15 × 1-2-3 ×0.5 = ×0.575   （罠）
1, 2, 3, 4, 6  →  FOUR STRAIGHT  ×1.35                         （4を作って脱出）
1, 2, 3, 4, 5  →  FIVE STRAIGHT  ×1.7

これにより、Tune Up で4を作る、Recycle で1か2を捨てるといった対処が意味を持つ。

7.4 ワイルド

Wild Die は役判定において任意の目として扱われる。実装はワイルドに割り当てうる目の全組み合わせを評価し、最も倍率が高くなる解釈を採用する。

この方式により、ワイルドが自分から減算役を成立させることはない（より高い倍率の解釈が選ばれるため）。また 1・2・3 が揃っている手札でも、ワイルドが4になることで STRAIGHT として脱出できる。

7.5 手札枚数の条件

手札全体を条件とする役（SAME NUMBER / EVEN / ODD）には最低枚数がある。1枚だけの手札が自動的に成立してしまうことを防ぐためで、minHandSize としてデータに持たせている。

8. 能力

能力はすべて { type, value?, duration? } 形式のデータとして定義する。

8.1 使用時能力（onUseAbility）

攻撃カードを使用した瞬間に発動する。

8.2 常在能力（passiveAbility）

カードが手札にある間つねに有効。手札の構成が変化するたびに再計算する。

手札には明確な順番があり、UI上も左から右へその順で表示する。RIGHT_CARD_ATTACK_BONUS はこの並び順に依存するため、Reorder で並びを操作できる。

8.3 戦術能力（tacticalAbility）

戦術カードは攻撃せず、ターンも終了しない。ポイントが続く限り同一ターン中に何枚でも使用できる。

なぜ独立したカテゴリなのか

役はカード使用の直前に判定されるため、使用時能力として目を変更しても、その攻撃の倍率には反映されない。さらに手札はターン終了時に総入れ替えされるため、次ターンにも残らない。目を操作する能力は「攻撃する前に、ターンを終了せずに」使えなければ効果が届く先がない。

目の変更の永続性

Tune Up / Tune Down / Overclock による目の変更はその戦闘の間ずっと残る。baseDieValue と比較して変化を検出し、UI上は TUNED 2→1 のように表示する。手札が毎ターン捨てられる仕様上、1ターン限りの効果ではコストに見合わないためである。山札は約4ターンで一巡するので、変更したカードは戦闘中に再び手札へ戻る。

目は1〜6の範囲に収める（範囲外にはならず、上限・下限で止まる）。

8.4 一時効果（temporaryEffects）

使用時能力などで発生した一時的な効果を配列で管理し、有効ターンを過ぎたら取り除く。

{
  type: "ATTACK_BONUS",
  value: 5,
  activeFromTurn: 3,
  expiresAfterTurn: 3,
  source: "Boost 2"
}

9. ダメージ計算

加算をすべて済ませてから役倍率を掛ける。したがって倍率は常在・一時効果の分も増幅する。

FinalAttack = Math.round(
  ( BaseAttack + PassiveBonus + TemporaryBonus ) × HandRoleMultiplier
)

9.1 計算例

Base Attack     10
Passive Bonus   +5   （左隣の Support 3 による）
Temporary Bonus +5   （前ターンの Boost 2 による）
手札            1 / 3 / 5  →  ODD ×2.8

(10 + 5 + 5) × 2.8 = 56 ダメージ

9.2 カード使用時の処理順

1.  使用可能か確認（コスト ≤ 現在ポイント）
2.  使用前の手札で役を判定
3.  常在能力を確認
4.  一時効果を確認
5.  最終攻撃力を計算
6.  ポイントをコスト分消費
7.  使用時能力を発動
8.  CPUへダメージ
9.  使用カードを手札から取り除く
10. 捨て札へ移動
11. 常在能力・役を再計算
12. 勝敗判定

役判定は必ずカードを手札から取り除く前に行う。

10. 敵（CPU）

1回の戦闘には同じ種類の敵が2体出る（src/data/enemies.js の ENCOUNTER）。2体の合計が旧仕様の1体（HP100・1ターン平均14ダメージ）と同じになるよう、1体あたり HP50、行動パターンの数値は半分にしてある。2体の行動周期はそろっており、同じターンに同じ行動をする。

敵はカードを使用せず、行動パターン（CPU_ACTION_PATTERN）を先頭から1ターンに1つずつ実行する。末尾の次は先頭に戻る。ランダム性はない。

各敵の次の行動（行動予告）、パターン全体・現在位置、溜め込み・ブロックの残量は常に画面に表示される。予告された行動がそのまま実行される。

intent = enemy.actionPattern[enemy.actionIndex]
enemy.actionIndex = (enemy.actionIndex + 1) % enemy.actionPattern.length

現在のパターンは ATTACK 7 → CHARGE +7 → ATTACK 14 → BLOCK 15 の4ターン周期。3ターン目の攻撃は溜め込み分が乗って 21 になる（2体で42）。1体の1周の与ダメージ合計は28で、2体合わせて1ターン平均14。

10.1 攻撃の対象

攻撃カードは対象の敵1体（個人攻撃）に当たる。対象は敵の欄をクリックして選び、選んだ敵には ◎ TARGET と枠を表示する。初期値は先頭の敵。選んだ対象はターンをまたいで保たれる。倒れた敵は選べず、対象が倒れると生き残っている先頭の敵に移る。攻撃プレビューは対象とそのブロックを表示する。

10.2 ブロック

ブロックは敵ごとに持ち、その敵への攻撃だけを防ぐ。その敵が行動するたびに（行動の解決前に）0へ戻す。つまり BLOCK の効果は直後のプレイヤーターン1回限り。そのターン中は複数枚の攻撃で共有して削られる。攻撃プレビューもブロック分を含めて表示する（プレビューではブロックを消費しない）。

blocked = Math.min(target.block, finalAttack)
dealt   = finalAttack - blocked
target.block -= blocked
target.hp    -= dealt

10.3 敵のターン

生き残っている敵が先頭から順に行動する。倒れた敵は行動しない。プレイヤーのシールドは敵の攻撃を順に吸収していく。途中でプレイヤーのHPが0になった時点で敗北となる。

敵が攻撃しないターン（CHARGE・BLOCK）はシールドが無駄になるため、そのターンは防御を捨てて攻めに回せる。ブロック中の敵がいるターンは、もう一方の敵を狙う、攻撃を控えて Boost（次ターン攻撃力アップ）などの準備に回す、といった判断がある。

行動効果
ATTACK nn + enemy.charge のダメージ。シールドで吸収した残りを player.hp から引き、enemy.charge を0に戻す
CHARGE n攻撃しない。enemy.charge += n
BLOCK n攻撃しない。enemy.block = n。直後のプレイヤーターン中、その敵への攻撃を合計 n まで防ぐ

11. 勝敗

  • プレイヤーの攻撃後にすべての敵のHPが0以下 → YOU WIN（敵のターンへ進まず終了）
  • 敵の攻撃後にプレイヤーHPが0以下 → GAME OVER

HPは0未満にならない。

11.1 連戦

勝利すると REWARD で報酬画面（11.2）に進み、そこから NEXT BATTLE で次の戦闘に進む。何戦目かと今のデッキ枚数は画面上部に BATTLE #002 DECK 9 のように表示する。

  • 引き継ぐもの：プレイヤーの残りHP（回復しない）と、報酬で入手・削除したデッキ
  • リセットするもの：山札（その時点のデッキから作り直してシャッフル）・ポイント・シールド・ターン数・敵（HP・行動パターンの位置・溜め込み・ブロック）・攻撃の対象
  • 敵は毎戦同じ（2体・HP・行動パターンとも変わらない）

敗北すると RETRY FROM #001 で1戦目からやり直す。デッキも構築画面のデッキに戻る。敗北画面には何戦目で敗れたかを表示する。EDIT DECK で構築に戻った場合も、次の戦闘は1戦目から始まる。

11.2 報酬（成長）

勝利後の報酬画面で、デッキを育てる。どちらも任意で、選んだ内容は NEXT BATTLE を押した時点で確定する。

  • 入手：カード一覧全体から重複なし・等確率で選んだ3枚の候補から1枚までを選んでデッキに加える。
  • 削除：今のデッキから1枚まで削除する。入手分を含めたデッキが最小枚数（6枚）を下回る削除はできない。
  • 構築画面の制約（目の上限・同名の上限・最大20枚）は、連戦中のデッキには掛けない。

報酬画面には残りHP、今のデッキの全カードと枚数、確定後のデッキ枚数、現在の役のレベルを表示する。ロジックは src/game/rewardLogic.js、枚数は REWARD_RULES で管理する。

11.3 役の強化

報酬画面では、カードの入手・削除とは別に、ボーナス役から重複なし・等確率で選んだ3つの候補のうち1つまでを強化できる（任意）。強化するとその役のレベルが1上がり、倍率に +0.1（ROLE_GROWTH.UPGRADE_STEP）を足す。

倍率 = 元の倍率 + レベル × 0.1     // 例：PAIR ×1.1 → Lv2 で ×1.3
  • 系統をまたいで倍率は掛け合わさるため、強化は掛け算ではなく足し算にしている。
  • 減算役（1-2-3）は強化の対象外。
  • 系統ごとに採る役は、強化後の倍率で比べる。そのため強化した下位の役が上位を追い越すことがある（例：PAIR を ×1.3 にすると、TWO PAIR ×1.25 の手札でも PAIR を採る）。ワイルドの目の選び方も強化後の倍率に従う。
  • レベルは連戦中に引き継ぎ、1戦目からやり直すと0に戻る。
  • 上げ幅は当面一律。役の成立しやすさに合わせた調整は今後行う。

戦闘中の役一覧（「役」ボタン）と報酬画面の役一覧には、強化後の倍率と元の倍率・レベルを表示する。

12. 状態

type GameState = {
  battle: number;               // 連戦の何戦目か（1始まり）
  pointRules: { startPoint: number; maxPoint: number; recovery: number; fullRefill: boolean };
  roleLevels: { [roleId: string]: number }; // 役の強化レベル（連戦中に引き継ぐ）
  turn: number;
  phase: GamePhase;

  player: {
    hp: number; maxHp: number;
    point: number; maxPoint: number;
    deck: Card[]; hand: Card[]; discardPile: Card[];
    cardsPlayed: number;          // 実際に使用した枚数（捨て札枚数とは別）
    temporaryEffects: TemporaryEffect[];
  };

  enemies: Array<{
    id: string; name: string;     // "enemy_1", "AEGIS A"
    hp: number; maxHp: number;
    actionPattern: CpuAction[];   // 先頭から順に実行し、ループする
    actionIndex: number;          // 次に実行する行動（予告）の位置
    charge: number;               // CHARGE で溜めた、次の ATTACK への上乗せ分
    block: number;                // BLOCK の残量。その敵が次に行動するとき0に戻る
  }>;
  targetId: string;               // 攻撃の対象の敵
  lastCpuActions: EnemyActionResult[]; // 直前の敵ターンで各敵が行った行動

  selectedCardId: string | null;
  currentRole: HandRoleResult | null;
  lastAttack: AttackResult | null;
  battleMessage: string;
};

手札は毎ターン捨て札を経由するため、捨て札の枚数は「使用したカードの枚数」と一致しない。使用枚数は cardsPlayed で別に数える。
